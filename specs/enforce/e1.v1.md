# E1 — Action model + policy engine v0.1 (`packages/unified-enforce`)

Status: implemented (v0.0.1). Decisions here flow from [technologies.md](../../technologies.md);
this spec is the ADR of record for the engine's v1 formats. This is the document design
partners critique (Linear milestone E1).

The engine does three things, in order, for every agent action:
**canonicalize → decide → record.** Nothing in the decision path performs I/O or
touches the network.

## §1 Action model (`unified.action/v1`)

One Action = one tool call / API request / data operation, normalized to:

```json
{
  "schema_version": "unified.action/v1",
  "id": "<ULID>",
  "ts": "<ISO-8601 UTC, microseconds>",
  "principal": {"id": "agent:claude-code", "kind": "agent", "session_id": null, "labels": {}},
  "tool": "mcp://github/create_pr",
  "verb": "call",
  "resource": "repo:acme/api",
  "params": {"title": "fix"},
  "context": {"origin": "mcp", "workspace": null, "trace_id": null, "span_id": null, "extra": {}}
}
```

- `id` is a ULID — unique per *observed* action; two identical operations get
  different ids but the same content `digest()`.
- `ts` is a string, not a datetime: canonical bytes must round-trip through JSON
  exactly.
- `principal.id` is namespaced (`agent:` / `user:` / `service:`); `kind` is the
  coarse class. `tool` is a URI (`mcp://<server>/<tool>`, `sdk://…`, `https://…`).
  `resource` is what is acted on (`repo:acme/api`, `db:prod/billing`, `*` when the
  interceptor can't tell).
- Models are pydantic v2 with `extra="forbid"`; JSON Schema is exportable for the
  published format (Public Release milestone).

## §2 Canonicalization

Same data → same bytes → same digest, across processes and machines.

- JSON with sorted keys, no whitespace, `ensure_ascii=False`, UTF-8.
- **Floats are forbidden** in canonical payloads (their repr is not portable across
  serializers). Money and measures enter as strings or ints at the schema boundary.
  Durations in audit records are integer microseconds (`elapsed_us`).
- Non-JSON scalars are rejected, never silently `str()`-coerced.
- `digest = SHA-256(canonical_bytes)`, hex.

## §3 Signing

Ed25519 (`cryptography`) over `action.canonical()`. `SignedAction = {action, key_id,
signature(base64)}`. A verified SignedAction is byte-exact proof of what was decided —
replayable offline. Key custody is out of scope here: OS keyring locally, KMS/HSM in
enterprise (per technologies.md).

## §4 Policy v0.1 — YAML rules + CEL conditions

> Superseded in part by [policy.v2.md](policy.v2.md) (v0.2: principal lists,
> args operator matchers, floors tier — the hub's ADR-0006 constructs absorbed).
> Everything below still holds; v0.2 is a strict superset.

Generalizes the hub's three-state resolver (ADR-0006) to all four action axes:

```yaml
version: 1
rules:
  - id: small-refunds-ok
    match:                      # all four axes are globs; omitted axis = "*"
      principal: "agent:*"
      tool: "sdk://payments/refund"
      verb: "call"
      resource: "*"
    when: 'int(params.amount_cents) <= 5000'   # optional CEL
    effect: allow               # allow | deny | defer
    audit_level: standard       # minimal | standard | detailed | full
    reason: "auto-approve small refunds"
```

**Globs:** `*` matches any run of characters except `/` (URIs stay segment-aware);
`**` also crosses `/`; a bare `*` leaves the axis unconstrained.

**Precedence** (matches the hub): ① exact rules — no wildcard in the `tool`
pattern — in file order; ② wildcard rules, first match wins; ③ implicit
default-deny, not configurable.

**CEL:** compiled once at policy load (`cel-python`); load fails on a bad
expression or duplicate rule id. Evaluation names: `action`, `principal`, `tool`,
`verb`, `resource`, `params`, `context`. A condition that evaluates `false` makes
the rule not match (fall through). A condition that **errors or returns non-bool
is an immediate DENY** (`source: condition_error`) — never a fall-through, because
a skipped deny is an accidental allow.

**Decision:** `{verdict: ALLOW|DENY|DEFER, rule_id, source: exact|wildcard|default|
condition_error, audit_level, reason, elapsed_ms}`. DEFER hands off to the approval
contract (M0.8); the engine itself never blocks waiting for a human.

Budget: <10 ms per decision. The test suite enforces this (100-call average with a
CEL rule in path; measured ~µs–low-ms today).

## §5 Audit chain

Evolves the hub's two-phase JSONL writer (ADR-0009) into a tamper-evident chain:

```
entry = {kind, seq, ts, prev_hash, payload, hash}
hash  = SHA-256(canonical_bytes(entry minus hash))
```

- `prev_hash` links every entry to its predecessor; genesis is 64 zeros. One chain
  spans daily `<UTC-date>.jsonl` files (day N+1's first entry links day N's last).
- Single writer (`fcntl` lock on `.lock`), `O_APPEND`, 0600/0700 modes; page-cache
  writes with fsync at rotation and shutdown — the hub's durability posture.
- Restart recovers `head`/`seq` from the last entry on disk.
- `AuditChain.verify(dir)` replays everything offline and reports the first break:
  edit → `hash mismatch`; deletion → `chain break`. This is the "court-grade,
  replayable offline" property the one-pager sells.
- `append_decision(action, decision)` is the standard record: full action dump +
  digest, verdict, rule id, source, reason, `elapsed_us`.
