# E3 — Gateway & egress enforcement (scaffold)

Status: **scaffolded** (core + HTTP transport implemented; gRPC transport and
egress templates open). Linear milestone E3 · Gateway & egress enforcement.
Locked stack: Envoy + ext_authz gRPC, no homegrown proxy (technologies.md §2).

## §1 Shape

Three layers, so the transport is swappable without touching enforcement:

1. **`ExtAuthzCore.check()`** (implemented) — transport-agnostic. Intercepted
   request attributes → canonical Action → `Enforcer` (decide + chain + span) →
   `CheckResult`. The Action: tool = `https://<host><path>`, verb = HTTP method,
   `origin: gateway`, resource `*` (network layer sees no business semantics —
   that's the SDK's job, E4). `traceparent` is parsed into
   `context.trace_id/span_id`, so gateway verdicts join the caller's trace.
2. **HTTP transport** (implemented) — Envoy `http_service` ext_authz server via
   `create_http_service()` ([gateway] extra). 200 = allow, 403 = deny;
   `x-unified-verdict / -rule / -source / -action-digest` response headers.
   Principal from `x-unified-principal` (set by trusted infra), else
   `agent:unknown` → default-deny does its job.
3. **gRPC transport** (open — the locked target) — an
   `envoy.service.auth.v3.Authorization` servicer over the same core. Needs the
   vendored proto set (envoy/xds/pgv); tracked as the first E3 completion task.

## §2 Verdict mapping at the network layer

ALLOW → 200. DENY → 403. **DEFER → 403 + `x-unified-verdict: defer`** — fail
closed: the gateway has no interactive approval channel until the approval
contract (M0.8) is wired in; a deferred network call must not hang an Envoy
worker. Revisit with the approval integration (queue + retry semantics).

## §3 Envoy template

`packages/unified-enforce/deploy/envoy/ext_authz-http.yaml` — egress sidecar:
dynamic forward proxy, ext_authz with `failure_mode_allow: false` (engine down
⇒ deny), 50 ms auth timeout (budget is <10 ms), `x-unified-*` headers
allowlisted both directions. The **no-bypass guarantee is egress policy around
the sidecar** (NetworkPolicy / iptables / security-group templates per
deployment mode) — those templates are E3-proper work, not scaffold.
