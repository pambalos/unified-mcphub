# E4 — Unified AI SDK v0

Status: **v0 implemented** (`packages/unified-sdk`). Framework adapters are not
started. Linear milestone E4 · Unified AI SDK v0.

*The proxy is the lock; the SDK is the label.*

## §1 The gap this closes

E3 intercepts at the network layer, where an operation looks like
`POST https://api.stripe.com/v1/refunds` and nothing more. Policy can therefore
say "no POST to /v1/refunds" but never "no refund over $5,000". Body inspection
(E3 §9) narrows the gap by parsing payloads, but it is still guessing at
meaning from bytes: it cannot tell a refund from a chargeback reversal that
happens to share a schema, and it cannot see intent that never crosses a wire.

The SDK lets application code state what an operation *means* — intent,
amounts, data classes — and get a verdict on that. The CEL conditions already
in policy v0.2 finally have something worth binding against.

## §2 Shape

`UnifiedAI` produces ordinary canonical Actions with `origin: sdk`, so
SDK-declared and gateway-observed operations share one policy language, one
digest scheme, and one audit chain. Nothing here is a second enforcement
mechanism.

Three call styles, one decision path:

- `check(...)` → `Acting`, never raises. For callers that want to branch on the
  verdict (offer an approval path, fall back to a cheaper operation).
- `acting(...)` — a context manager that decides *before* the block and raises
  unless allowed, so a denied operation never starts.
- `@action(...)` — a decorator. `tool` and `resource` are format templates over
  bound arguments; `params` names the arguments to capture.

`UnifiedAI.local()` builds the whole stack from a policy file; the plain
constructor wraps an existing `Enforcer` so a process already running the
engine (the hub, a gateway) shares one chain instead of opening a second,
competing writer.

Decisions stay local and synchronous — no control-plane hop on the decision
path, which is what keeps them inside the latency budget and keeps a control
plane outage from becoming an outage of every agent.

## §3 Two properties that must not break

**Optional.** An application that never calls the SDK is still enforced at the
network layer. The SDK raises the *resolution* of policy; it is never what
makes enforcement happen. If skipping it granted more freedom, every agent
would skip it.

**Claims, not facts.** Annotations come from inside the trust boundary the
gateway is protecting — the application can lie, and a compromised agent
certainly will. Policy authors distinguish them via `context.origin`, and the
rule that follows is: **never grant more on an SDK claim than the network layer
would grant on its own.** Use annotations to *narrow* (deny a large refund the
network rules would have allowed), not to widen.

Two deliberate consequences:

- **Capture is explicit.** `params=["amount"]` names what policy needs.
  Sweeping every argument in would put API keys, tokens, and personal data into
  the audit chain by default, and an evidence log is the worst possible place
  to discover that.
- **Unknown names fail at decoration time**, not on the first call in
  production.

## §4 Correlation with the gateway (the ADR)

With both the sidecar and the SDK running, one logical operation produces two
observations: the SDK's semantic Action ("$8,000 refund, customer 42, PII") and
the gateway's network Action (`POST .../v1/refunds`). Three options were
weighed:

1. SDK pre-declares; the gateway **joins** on a correlation token and enforces
   the richer Action.
2. SDK decides locally; the gateway is a pure network-level backstop.
3. Both decide independently, both are recorded and linked.

**Chosen: 3, with the token from 1 used only for linking.**

Option 1 is tempting and wrong for v0: it makes the gateway's verdict depend on
a value the agent controls. A compromised agent would suppress or forge the
token to get the weaker of the two decisions, and the no-bypass guarantee would
rest on the honesty of the thing being guarded.

Under option 3 the "stricter wins" property is **structural rather than
implemented**: both layers enforce, so the operation must clear both. Nothing
in the engine has to compare verdicts.

The link itself: `Acting.headers` yields `x-unified-action: <digest>` (plus a
`traceparent` when an ambient OTel span exists). The sidecar records it as
`context.extra.sdk_action_claimed` — validated for shape, so the chain cannot
be used as a scratchpad for arbitrary client text, but **never trusted**. It
cannot change a verdict. A forged value only adds a false link, which is why it
is recorded as *claimed* and why only the SDK's own chained entry is
authoritative. The templates strip the header before the request reaches the
upstream, so it never leaks to third parties.

Reusing `traceparent` rather than inventing a second mechanism means gateway
verdicts, SDK verdicts, and application spans already share a trace when
tracing is configured. When it is not, no trace id is fabricated — a synthetic
id that links nothing is worse than its absence.

## §5 Canonicalization of annotated values

Amounts are the whole point of this SDK and amounts are exactly what strict
canonicalization refuses: floats have no portable repr, so a signed action
carrying one would not verify on a non-Python verifier.

`float` and `Decimal` params are therefore normalized to **strings**, matching
what the gateway's body parser produces (`parse_float=str`, E3 §9). The same
refund annotated by the SDK and observed by the sidecar canonicalizes
identically, instead of one of the two failing to sign. `repr` on a float is
its shortest round-tripping form. In CEL: `double(params.amount) > 5000`.

## §6 Verification

`packages/unified-sdk/tests/unit/` — 30 tests. The ones carrying real weight:

- the value inside `params` decides the verdict (same tool, same verb);
- a denied action's function body never runs, sync **and** async (a sync
  wrapper around a coroutine would decide, then return a coroutine that runs
  the real work after the guard exited — authorized, but at a misleading
  moment);
- only named params are captured, so a secret passed alongside them stays out
  of the chain;
- floats and Decimals survive as exact strings and the digest still computes;
- both observations land in one chain and can be joined by digest;
- **a forged correlation header cannot change the verdict**, and an SDK allow
  cannot unlock an egress the gateway denies.

## §7 Open

- **Framework adapters** (LangChain / CrewAI / MCP) — UAI-132. The hub already
  demonstrates the MCP-shaped case end to end, so that adapter is mostly
  extraction rather than new design.
- **DEFER has no resolution path.** `ApprovalRequired` is raised and that is
  where it ends, pending the approval contract moving into the engine
  (UAI-133). The exception exists now so that path is a change to one class
  rather than a new error type later.
- **No signing by default.** Actions are canonical and digestible, but the SDK
  does not sign them; `Signer` is available and unwired. Signing matters most
  when actions cross a trust boundary, which is C1/C2 territory.
